## Define the job first

State the capability you need, who will operate it, how often, and what happens if it fails. Compare tools only after writing these requirements. A popular product may be a poor fit if it creates an unnecessary integration, unclear data handling, or a costly migration path.

## Check the real operating cost

Review current official pricing and usage limits, export formats, support, uptime commitments, authentication options, data processing and retention, and cancellation. Estimate cost at plausible usage rather than only the free tier. Try the most important workflow with realistic data and include migration effort in the comparison.

The supplied Tech Stack PDF is a dated lead list; its feature and price comparisons should not be copied as current recommendations. Record the date and links for any live comparison. Prefer a boring, well-documented option the team can operate, and revisit it when a concrete constraint changes. Keep critical product data portable where practical.

# IndieWiki knowledge base

This document defines the site’s topic map. The repository is canonical; the static website publishes reviewed Markdown rather than keeping a separate copy.

## Initial map

Organize pages around builder tasks and cross-link shared concepts.

1. **Start:** problems, customers, markets, niches, founder/market fit, idea evaluation.
2. **Validate:** interviews, demand, competition, landing-page tests, prototypes, concierge MVPs, pre-sales, waitlists, fake-door tests.
3. **Product:** strategy, MVP, requirements, stories/flows, UX/UI, onboarding, states, notifications, prioritization.
4. **Build:** architecture, frontend/backend, data, auth, APIs, storage, search, email, payments, jobs, analytics, errors.
5. **AI Build:** coding tools, prompting, context, planning, review, verification, testing, security, agents, permissions, maintenance.
6. **Tech Stack:** domains, hosting, frameworks, backend platforms, databases, auth, email, payments, analytics, infrastructure.
7. **Security:** secure development, privacy, access control, dependencies, backups, incident response.
8. **Ship:** release readiness, deployment, observability, launch planning, learning.
9. **Grow:** positioning, distribution, SEO, content, partnerships, sales, first users.
10. **Monetize:** pricing, packaging, billing, payments, business models.
11. **Retain:** activation, onboarding, support, reliability, engagement, churn.
12. **Operate:** support, analytics, maintenance, compliance awareness, sustainable workflows.
13. **Business:** finance, legal, tax, operations, with jurisdiction stated.
14. **Resources:** templates, checklists, glossaries, annotated references.

## Page status

A topic on the map is not an approved article. Start with a focused issue or pull request, verify evidence, and follow [the content guide](CONTENT_GUIDE.md), [source policy](SOURCE_POLICY.md), and [authoring notes](src/content/README.md). Article metadata is validated by the static build.

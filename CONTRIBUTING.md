# Contributing to IndieWiki

Help independent builders find practical, trustworthy guidance. Contributions may fix a typo, flag an outdated claim, improve a citation, add a perspective, or propose a page.

## Workflow

1. Search existing pages and issues.
2. Open an issue before a new topic, major restructuring, broad tool comparison, or sensitive/high-impact advice. Small corrections can go straight to a pull request.
3. Make a focused change on a branch and submit a pull request.
4. Explain what changed, why, evidence added, and remaining uncertainty.
5. Respond to review and improve citations/context as needed.

Keep unrelated edits separate. Never submit secrets, personal data, private customer material, or assets without suitable permission.

## Pull request expectations

For a new article or material revision:

- Follow [CONTENT_GUIDE.md](CONTENT_GUIDE.md) and [SOURCE_POLICY.md](SOURCE_POLICY.md).
- Identify audience, scope, assumptions, and relevant jurisdiction.
- Cite evidence near the claims it supports; date volatile details.
- Explain material trade-offs, alternatives, and uncertainty.
- Label first-hand experience and examples honestly.
- Use original wording and accessible headings, links, tables, and image descriptions.

A typo or link fix does not need an elaborate evidence section; state when an item does not apply.

## Review and conduct

Be constructive and focus on accuracy, usefulness, scope, and evidence. Maintainers may request revisions, defer, or decline with an explanation. Participation does not guarantee acceptance. Avoid merging your own substantial changes without independent review when another maintainer is available.

Treat people respectfully; critique edits, not contributors. Harassment, discrimination, spam, and undisclosed commercial promotion are not acceptable. Maintainers may moderate under [GOVERNANCE.md](GOVERNANCE.md).

## Reporting problems

Use GitHub issues for corrections, outdated pages, source problems, missing topics, and proposals. Do not post sensitive security/privacy details publicly. Contact a maintainer privately using a channel published in the repository profile/project home; if none exists, post only enough to request one.

Exact branch protections, review counts, issue templates, and service targets are not established. Do not assume GitHub enforces them.
